Magic Carpet File Format Specification
=======================================
Bullfrog Productions, 1994
Originally documented by Michael Howard (2011)
Updated 2025 with complete reverse engineering

Overview
--------
Magic Carpet stores level data in RNC-compressed binary files. The terrain is
PROCEDURALLY GENERATED from seed parameters at runtime - there is no heightmap
stored in the level files. Entity placement (creatures, scenery, spells, etc.)
is stored as a fixed-size table of 18-byte records.

The key breakthrough came from examining the GAM*.DAT save game files, which
are plain TEXT representations of the same data structure with full field names
(GEN_MAP and THING_INIT column headers). This acts as a Rosetta Stone for the
binary format.


Compression
-----------
All .DAT and .INF files use Rob Northen Compression (RNC) method 1.
Compressed files begin with the magic bytes: 52 4E 43 01 ("RNC\x01")

RNC Header (18 bytes):
  Offset  Size  Description
  0x00    3     Magic "RNC"
  0x03    1     Method (0x01)
  0x04    4     Uncompressed size (big-endian)
  0x08    4     Compressed size (big-endian)
  0x0C    2     Uncompressed CRC
  0x0E    2     Compressed CRC
  0x10    1     Leeway count
  0x11    1     Pack chunks

-------------------

  CARPET.EXE          DOS4GW 32-bit protected mode executable
  DOS4GW.EXE          DOS extender

  /LEVELS/
    LEVELS.TAB         Offset table into LEVELS.DAT (uint32 LE per level)
    LEVELS.DAT         All level .DAT files concatenated (RNC compressed)
    LEV00000.DAT       Individual level data (RNC compressed)
    LEV00000.INF       Level content summary (RNC compressed text)
    ...
    LEV00069.DAT       Level 69 (70 total levels, 0-indexed)
    ALL.INF            All .INF files concatenated (RNC compressed text)
    GAM*.DAT           Save game files (RNC compressed TEXT format)
    STATE.RST          State reset file (239 bytes uncompressed)


LEVELS.TAB - Level Offset Table
--------------------------------
Array of uint32 little-endian values, one per level.
Each value is a byte offset into LEVELS.DAT where that level's compressed
data begins. Unused slots (beyond level 69) repeat the final valid offset.

Example:
  Level 0: offset 0x00000000
  Level 1: offset 0x00000867
  Level 2: offset 0x00000E07
  ...


LEV*.DAT - Level Data Files (Binary Format)
=============================================
All levels decompress to exactly 38,812 bytes (0x979C).

File Layout:
  Offset      Size      Description
  0x0000      48        Map Generation Header (GEN_MAP)
  0x0030      1042      Reserved block (all zeros in known levels)
  0x0442      37710     Entity Table (2095 slots x 18 bytes)
  0x9790      12        Footer (level metadata)
  -------     -----
  Total:      38812 bytes


Section 1: Map Generation Header (GEN_MAP)
-------------------------------------------
48 bytes = 12 x uint32 little-endian values.

The first uint32 is a pre-header field NOT present in the GEN_MAP text format.
The remaining 11 fields were identified by cross-referencing GAM00088.DAT
(a save game from Level 65) against the Level 65 binary header - all 11
GEN_MAP values matched at offsets 0x04-0x2C exactly.

  Offset  Size  Field    Description
  0x00    4     (unk)    Pre-header field (not in GEN_MAP; possibly checksum
                         or level ID. Varies: 135538, 110315, 69024, ...)
  0x04    4     Seed     Terrain generation seed
  0x08    4     Off      Terrain height offset (base elevation)
  0x0C    4     Raise    Terrain raise amount (SIGNED; negative = sunken)
  0x10    4     Gnarl    Terrain roughness/fractal detail (0=smooth, 128=extreme)
  0x14    4     River    Number of rivers (0=none, typical=18, max seen=60)
  0x18    4     Sourc    Number of river source points (springs)
  0x1C    4     SnLin    Snow line height threshold (200=very high=no snow)
  0x20    4     SnFlt    Snow flat parameter (texture blending)
  0x24    4     BhLin    Beach line height threshold
  0x28    4     BhFlt    Beach flat parameter (texture blending)
  0x2C    4     RkSte    Rock steepness threshold (how steep = rock texture)

The terrain engine uses these parameters to procedurally generate the voxel
landscape at runtime. There is no stored heightmap - the same seed always
produces the same terrain.

Terrain Generation Pipeline
-----------------------------
The engine generates terrain in two phases (confirmed by strings in CARPET.EXE:
"Generate map" followed by "Generate features").

Phase 1 - "Generate map": Base terrain from parameters
  1. Seed determines the fractal noise pattern (256x256 logical grid)
  2. Off sets the base height offset for the entire map
  3. Raise adds/subtracts elevation globally (negative = terrain below sea level)
  4. Gnarl controls fractal roughness (0=gentle rolling hills, 128=extreme crags)

Phase 2 - "Generate features": Rivers and surface types
  5. River rivers are carved into the terrain from Sourc source points
  6. Rivers flow downhill from source points toward the ocean
  7. Texturing is applied based on height and slope:
     - Above SnLin: snow (SnFlt controls blending)
     - Below BhLin: beach/sand (BhFlt controls blending)
     - Steeper than RkSte: rock face texture
     - Everything else: grass/earth


River System Details
---------------------
Analyzed across all 70 levels. 50 of 70 levels have river-related parameters.

The River field controls the number of river channels. The Sourc field controls
the number of spring/source points where rivers originate on high ground.

Common presets found across levels:
  River=18 Sourc=47   "Standard rivers" - used by 12 levels (1,14,16,19,22,23,28,29,30,41,62,63)
  River=18 Sourc=132  "Dense rivers"    - used by 3 levels (40,43,45)
  River=29 Sourc=0    "Wide rivers"     - used by 3 levels (10,35,64)
  River=0  Sourc=47   "Springs only"    - used by 5 levels (32,39,67,68,69)
  River=1  Sourc=183  "Single river"    - used by 2 levels (27,51)

Extreme configurations:
  Level 42: Gnarl=128 River=38 Sourc=39  (extreme terrain + many rivers)
  Level 39: Gnarl=106 River=0  Sourc=47  (extreme terrain + springs only)
  Level 18: Gnarl=83  River=35 Sourc=100 (rough terrain + dense water network)
  Level 50: All zeros                     (completely flat/submerged - special level)

Rivers interact with the terrain height: source points are placed on elevated
terrain, and rivers carve channels downhill to the sea. The BhLin (beach line)
parameter affects how wide the shoreline is where rivers meet the ocean.


Section 2: Reserved Block
--------------------------
Offset 0x0030 - 0x0441 (1042 bytes)
All zeros in every examined level (0-5). Purpose unknown.
Possibly reserved for runtime state, expansion, or map overlay data.


Section 3: Entity Table (THING_INIT Records)
----------------------------------------------
Offset 0x0442 - 0x978F
2095 fixed slots, each 18 bytes. Empty slots are all zeros.

Field names from the GAM text format's THING_INIT columns:
  //  Class  Model  Xpos  Ypos  DisId  SwiSz  SwiId  Paren  Child

  Offset  Size  Field    Description
  0x00    2     Class    Entity class/type (uint16 LE)
  0x02    2     Model    Entity model/subtype (uint16 LE)
  0x04    2     Xpos     X position on map grid (uint16 LE)
  0x06    2     Ypos     Y position on map grid (uint16 LE)
  0x08    2     DisId    Disposition ID (uint16 LE, 0xFFFF = none)
  0x0A    2     SwiSz    Switch Size (uint16 LE)
  0x0C    2     SwiId    Switch ID (uint16 LE, 0xFFFF = none)
  0x0E    2     Parent   Parent entity index (uint16 LE, 0 = none)
  0x10    2     Child    Child entity index (uint16 LE, 0 = none)

Parent/Child fields form linked lists. Path entities (Class 10, Model 29)
use these to chain waypoints together. Wizard entities use Parent to reference
their path or group.

Section 4: Footer
------------------
Offset 0x9790 - 0x979B (12 bytes)
6 x uint16 little-endian values.

  Offset  Size  Description
  0x00    2     Unknown parameter (varies: 35, 40, 45, 44, 55, 55)
  0x02    2     Unknown parameter (1 for early levels, 2 for later)
  0x04    8     Zeros / reserved

Purpose unclear. May relate to difficulty, initial mana, or AI behavior.


LEV*.INF - Level Information Files (Text Format)
==================================================
RNC-compressed text files. When decompressed, contain a human-readable
summary of level contents with entity counts.

Format:
  //levels/lev00000.inf
  //map contents list
  //
  class              model                   amount
  ------------------------------------------------
  Scenery            Tree                    = 419
  Scenery            Standing stone          = 12
  Player             Flyer1                  = 1
  Creature           Vulture                 = 9
  ...

Followed by a detailed per-entity listing of class and model.


ALL.INF - Combined Level Information
======================================
RNC-compressed text file containing all individual .INF files concatenated.


GAM*.DAT - Save Game Files (Text Format)
==========================================
RNC-compressed TEXT files (not binary!). These are the Rosetta Stone
for understanding the binary LEV*.DAT format, as they contain the
exact same data with labeled column headers.

Format:
  //map generation parameters
  //          Seed  Off   Raise Gnarl River Sourc SnLin SnFlt BhLin BhFlt RkSte
  //          -----------------------------------------------------------------
  GEN_MAP     08538 05123 01726 00000 00060 00027 00200 00050 00032 00016 00013

  //list of inits to be generated at run time
  //          Class Model Xpos  Ypos  DisId SwiSz SwiId Paren Child
  //          -----------------------------------------------------
  THING_INIT  0001  00010 00045 00144 00048 65535 00000 65535 00013 00000
  THING_INIT  0002  00005 00013 00157 00045 00000 00000 00000 00000 00000
  ...

All values are decimal. 65535 = 0xFFFF = "none/unused".
The THING_INIT index (0001, 0002...) is 1-based; in the binary format,
entity slots are 0-based by file position.


STATE.RST - State Reset File
==============================
Small file (239 bytes uncompressed). Purpose likely relates to
resetting game state between levels.


Verification
-------------
The complete file structure is verified:
  Header (48) + Reserved (1042) + Entities (2095 * 18 = 37710) + Footer (12)
  = 38,812 bytes = 0x979C

This matches every decompressed LEV*.DAT file examined.

Entity counts from binary parsing match the .INF text summaries exactly
(545 active entities in Level 0 when excluding empty slots and padding).

Unknowns / Future Work
------------------------
- Header field at offset 0x00: not part of GEN_MAP; purpose unknown
  (varies widely per level: 135538, 110315, 69024, 661980, ...)
  Could be a checksum, packed flags, or level version identifier
- Reserved block at 0x0030-0x0441: always zeros across all 70 levels;
  may hold data in modded levels or be written to at runtime
- Footer values: correlation with gameplay parameters not yet determined
- Creature model 0x0F: gap between Trader(0x0E) and Wyvern(0x10), possibly
  the "None" creature type seen in the development ALL.INF
- Effect gaps (0x02-0x04, 0x07, 0x0A, 0x0C, 0x10, 0x12-0x16, 0x1A-0x1B,
  0x1E, 0x20-0x21, 0x23-0x26, 0x28-0x2C, 0x2E-0x30, 0x33): likely
  runtime-only spell visual effects, not placed in level files
- Effect model 0x31: 6 instances across all levels, no INF name match
- Player models 0x09 and 0x0B: Flyer6/Flyer7 ambiguous (identical counts)
- Exact terrain generation algorithm: fractal noise type unknown
  (likely diamond-square or Perlin noise variant, common in 1994)
- River carving algorithm: exact pathfinding method unknown
  (likely gradient descent from source to sea)
- Map coordinate system: coordinates go up to ~255 (uint8 range within uint16),
  suggesting a 256x256 logical grid
- CARPET.MAP: reportedly contains additional game data including planned but
  unimplemented creatures and features (familiars, weather, power-ups)
- Magic Carpet Plus / Magic Carpet 2: may use similar or extended formats
- Programmed by Sean Cooper (credited in CARPET.EXE strings)
